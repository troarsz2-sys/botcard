# คลังการ์ด BOT — Battle of Talingchan Collection

แอปจัดการคลังการ์ดสะสม **Battle of Talingchan (BOT)** สำหรับใช้ส่วนตัว
เป็นแอป **ฟรี ทำงานในเครื่องเป็นหลัก (local-first)** เก็บข้อมูลในเบราว์เซอร์ด้วย IndexedDB
ไม่ต้องสมัครสมาชิก ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องใช้ API key และไม่ต้องจ่ายเงิน

เขียนด้วย React + TypeScript + Vite + Tailwind CSS + IndexedDB (ผ่านไลบรารี `idb`)
ทดสอบด้วย Vitest และ deploy ลง GitHub Pages ได้ฟรี (ถ้าต้องการ)

> ภาษาของหน้าจอเป็นภาษาไทยเป็นหลัก

## 1. ติดตั้ง Node.js LTS

แอปนี้ต้องใช้ Node.js (แนะนำเวอร์ชัน LTS เช่น 20.x หรือใหม่กว่า)

1. ไปที่ https://nodejs.org/
2. ดาวน์โหลดเวอร์ชัน **LTS** สำหรับ Windows (ตัวติดตั้ง .msi)
3. เปิดตัวติดตั้ง กด Next ไปจนจบ (ใช้ค่าเริ่มต้น)
4. ปิดและเปิดเทอร์มินอลใหม่เพื่อให้คำสั่ง `node` / `npm` ใช้ได้

ตรวจสอบในเทอร์มินอล:

```powershell
node --version
npm --version
```

ถ้าเห็นเลขเวอร์ชันขึ้นมาแสดงว่าติดตั้งสำเร็จ

## 2. เปิดโปรเจกต์ใน Kiro

1. เปิด Kiro
2. ไปที่ **File > Open Folder…** (หรือ File > Open)
3. เลือกโฟลเดอร์โปรเจกต์นี้ (โฟลเดอร์ที่มีไฟล์ `package.json`)
4. รอสักครู่ให้ Kiro สแกนโฟลเดอร์เสร็จ

## 3. เปิดเทอร์มินอลของ Kiro

- เมนู **Terminal > New Terminal** หรือกดปุ่มเปิดเทอร์มินัลในแผงด้านล่าง
- ตรวจสอบว่าเทอร์มินัลอยู่ที่โฟลเดอร์โปรเจกต์ (เห็นพาธที่มี `package.json`)
- บน Windows ค่าเริ่มต้นใช้ PowerShell ก็ได้

## 4. ติดตั้ง dependency

ในเทอร์มินัล พิมพ์:

```powershell
npm install
```

รอจนติดตั้งเสร็จ (จะมีโฟลเดอร์ `node_modules` และไฟล์ `package-lock.json` ขึ้นมา)

## 5. เริ่มเซิร์ฟเวอร์พัฒนา

```powershell
npm run dev
```

เทอร์มินัลจะแสดงที่อยู่ เช่น `http://localhost:5173/`

## 6. เปิดแอปในเบราว์เซอร์

- กด Ctrl ค้างและคลิกลิงก์ `http://localhost:5173/` ในเทอร์มินัล หรือ
- เปิดเบราว์เซอร์แล้วไปที่ `http://localhost:5173/`

แนะนำให้ใช้ Chrome หรือ Edge

## 7. หยุดเซิร์ฟเวอร์พัฒนา

- คลิกที่เทอร์มินัลแล้วกด **Ctrl + C**
- ตอบ `Y` หรือกด Enter เพื่อยืนยันการหยุด

## 8. build เวอร์ชันสำหรับใช้งานจริง

```powershell
npm run build
```

ผลลัพธ์จะอยู่ในโฟลเดอร์ `dist/` นำไปเปิดหรือ host ได้ทันที (ใช้ relative path จึงเปิดจากโฟลเดอร์ย่อยได้)

ดูตัวอย่าง build ในเครื่อง:

```powershell
npm run preview
```

ทดสอบอัตโนมัติ:

```powershell
npm run test
```

## 9. นำเข้าข้อมูลการ์ด

เปิดหน้า **นำเข้า** ในแอป แล้วเลือก:

- **แคตตาล็อก CSV**: ใช้ไฟล์ตัวอย่าง `example-catalog.csv`
- **แคตตาล็อก JSON**: ใช้ไฟล์ตัวอย่าง `example-catalog.json`
- **คอลเลกชัน JSON**: ใช้ไฟล์ตัวอย่าง `example-collection.json`

ระบบจะตรวจซ้ำด้วย id และรหัสการ์ด แสดงพรีวิวก่อนนำเข้า และเก็บประวัติการนำเข้า

**คอลัมน์ CSV ที่รองรับ** (ชื่อหัวตารางยืดหยุ่นได้ ลองดูค่าใน `src/utils/importLogic.ts`):
`id, code, nameTh, nameEn, set, type, rarity, variant, imageUrl, sourceUrl, attribution, description, lastVerified, verified`

- ฟิลด์ที่บังคับ: `code` และ `nameTh`
- ฟิลด์อื่นปล่อยว่างได้
- ถ้าไม่มีหัวตาราง ระบบจะเดาตามลำดับคอลัมน์เริ่มต้น

**นำเข้าคอลเลกชันส่วนตัว**: ใช้ `cardId` หรือ `code` เพื่อโยงกับการ์ดในแคตตาล็อก
ฟิลด์: `cardId, code, owned, forTrade, condition, acquiredAt, purchasePrice, notes`

หรือกรอกการ์ดเองได้ที่หน้า **จัดการการ์ด**

> ค่าตัวอย่างในไฟล์ `example-*` เป็นตัวอย่าง (มีคำว่า "ตัวอย่าง"/"EXAMPLE") ไม่ใช่การ์ดจริง
> ดูเรื่องแหล่งข้อมูลและลิขสิทธิ์ในไฟล์ `SOURCES.md`

## 10. สำรอง/กู้คืนข้อมูล

เปิดหน้า **ส่งออก/สำรอง**:

- **สำรองข้อมูลเต็มรูปแบบ (JSON)**: รวมแคตตาล็อก คอลเลกชัน wishlist การตั้งค่า ประวัติการนำเข้า และ **รูปที่แนบเอง** (ฝังเป็น base64) ทำให้กู้คืนได้ครบ
- **กู้คืน**: เลือกไฟล์สำรองแล้วเลือกโหมด
  - **รวมข้อมูล**: ข้อมูลจากไฟล์ชนะตอน id/cardId ซ้ำ ส่วนที่มีเดิมและไม่ซ้ำจะคงไว้
  - **แทนที่ทั้งหมด**: ล้างข้อมูลปัจจุบันแล้วเขียนจากไฟล์ (โหมดนี้จะถามยืนยัน)
- ส่งออกแคตตาล็อก (CSV/JSON) และคอลเลกชัน (CSV) ได้ด้วย

> แนะนำให้สำรองข้อมูลเป็นไฟล์เป็นระยะ เพราะข้อมูลเก็บในเบราว์เซอร์เครื่องนี้เท่านั้น

## 11. deploy ลง GitHub Pages (ไม่บังคับ)

แอปเปิดในเครื่องได้โดยไม่ต้อง deploy ถ้าต้องการเผยแพร่:

1. สร้าง repository บน GitHub แล้ว push โปรเจกต์ขึ้นไป
2. ไฟล์ `.github/workflows/deploy.yml` ที่มาพร้อมโปรเจกต์จะ build และ deploy `dist/` อัตโนมัติเมื่อ push ไป branch `main`
3. บน GitHub ไปที่ **Settings > Pages > Build and deployment > Source: GitHub Actions**
4. รอ workflow ทำงาน แล้วจะได้ URL ของเว็บ

Vite ตั้ง `base: './'` ไว้แล้ว ทำให้ใช้ได้กับ project site (`https://ชื่อผู้ใช้.github.io/ชื่อrepo/`)
และใช้ HashRouter จึงรีเฟรชหน้าย่อยไม่เจอ 404

### ความเป็นส่วนตัวเมื่อ host สาธารณะ

โลคอลเท่านั้น (เปิด `npm run dev` หรือไฟล์ `dist/` ในเครื่อง) = ส่วนตัว เพราะข้อมูลเก็บในเบราว์เซอร์ของคุณ

แต่ **เว็บ static ที่ host บน GitHub Pages ไม่ใช่เว็บส่วนตัวแบบมีล็อกอิน**
ใครเข้าถึง URL ได้ก็เปิดหน้าแอปได้ อย่างไรก็ตาม **ข้อมูลคลังการ์ดของแต่ละคนยังเก็บแยกในเบราว์เซอร์ของตน**
เจ้าของ URL ไม่สามารถดูข้อมูลของผู้เปิดเว็บคนอื่นได้

ถ้าต้องการให้เป็นส่วนตัวจริง ๆ ให้ **เปิดใช้ในเครื่องเท่านั้น** หรือสร้างระบบล็อกอินแยกต่างหาก
(การซ่อน URL หรือไม่มีหน้าล็อกอิน ไม่ใช่การรักษาความปลอดภัย)

## 12. ข้อผิดพลาดที่พบบ่อยและวิธีแก้

| ปัญหา | วิธีแก้ |
|------|--------|
| `'node' ไม่จดจำเป็นคำสั่ง` / `'node' is not recognized` | ติดตั้ง Node.js LTS แล้วปิด/เปิดเทอร์มินัลใหม่ |
| `npm : ไม่พบคำสั่ง` | ติดตั้ง Node.js LTS (มี npm มาพร้อม) |
| พอร์ต 5173 ถูกใช้ | ปิดแอปที่ใช้พอร์ตนั้น หรือรัน `npm run dev -- --port 5174` |
| หน้าเว็บขาวหลัง deploy | ตรวจว่า build สำเร็จ และเปิดจาก URL ที่ GitHub ให้ รีเฟรชไม่เจอ 404 เพราะใช้ HashRouter |
| ข้อมูลหาย | ข้อมูลอยู่ในเบราว์เซอร์/โปรไฟล์นั้น ลองเบราว์เซอร์ปกติ (ไม่ใช่ InPrivate) หรือกู้คืนจากไฟล์สำรอง |
| รูปจาก URL ไม่ขึ้นเวลออฟไลน์ | รูป URL ภายนอกไม่ได้แคช; แนบรูปเองจะเก็บในเครื่องและใช้ออฟไลน์ได้ |
| `npm install` ช้า/ผิดพลาด | ลองลบ `node_modules` และ `package-lock.json` แล้ว `npm install` ใหม่ |

## โครงสร้างโปรเจกต์

```
src/
  components/   # องค์ประกอบ UI (Icon, CardTile, Layout, Modal, ฯลฯ)
  pages/        # หน้าต่าง ๆ (Dashboard, Catalog, Progress, Wishlist, Import, Export, Manual, Settings)
  state/        # AppContext (สถานะ + การกระทำ)
  database/     # ชั้น IndexedDB (db, repositories, exportService, backupService)
  hooks/        # useImage
  utils/        # csv, json, importLogic, backup, completion, quantity, ฯลฯ
  types/        # ประเภทข้อมูล
  main.tsx, App.tsx, index.css
tests/          # การทดสอบ Vitest
public/         # manifest, service worker, favicon
```

โครงสร้างนี้แยก **ชั้นฐานข้อมูล** ออกจาก **UI** อย่างชัดเจน

## ความเป็นส่วนตัว

- ไม่มีการสมัครสมาชิก ไม่มีผู้ใช้หลายคน ไม่มีการแชร์คลังการ์ด
- ไม่มี analytics/telemetry ไม่ส่งข้อมูลคลังการ์ดออกเซิร์ฟเวอร์
- ข้อมูลเก็บใน IndexedDB ของเบราว์เซอร์เครื่องนี้เท่านั้น (ไม่ข้ามเบราว์เซอร์/อุปกรณ์/บัญชีผู้ใช้ Windows)
- มีเครื่องมือสำรอง/กู้คืนเป็นไฟล์ให้เจ้าของ

ถ้าจะเพิ่มการซิงค์คลาวด์ในอนาคต ให้ถือเป็นโปรเจกต์แยก และต้องอธิบายค่าใช้จ่ายและความปลอดภัยก่อนทำ

## หมายเหตุเรื่องข้อมูลและลิขสิทธิ์

- แอปนี้ **ไม่ได้รวมข้อมูลการ์ดหรือรูปการ์ดจริงใด ๆ** มาในซอร์สโค้ด
- การ์ดตัวอย่าง (set = DEMO) เป็นข้อมูลประดิษฐ์ สำหรับทดลอง ลบได้จากหน้าตั้งค่า
- ดูรายละเอียดแหล่งข้อมูลและสิทธิ์ในไฟล์ `SOURCES.md`

## สิ่งที่ยังไม่ได้ทำ / ข้อจำกัด

- ไม่มีการนำเข้าอัตโนมัติจากเว็บ bottcg.com หรือ tamacard.com เพราะไม่พบ API/ชุดข้อมูลที่อนุญาตชัดเจน
- ไม่มีการซิงค์ข้ามอุปกรณ์ (เป็น local-first)
- เว็บที่ host สาธารณะไม่ใช่เว็บส่วนตัวแบบล็อกอิน
- รูปจาก URL ภายนอกไม่สามารถใช้ออฟไลน์ได้ (ต้องแนบรูปเอง)

จากนั้น:
1. เปิดแอป → คลิก **"ซิงก์ข้อมูลการ์ด"**
2. เลือกแท็บ **"ไฟล์ JSON"**
3. เลือกไฟล์ `bot-catalog.json`
4. กด **"นำเข้าและอัปเดตแคตตาล็อก"**

### การซิงก์ทำงานอย่างไร

- แอปดาวน์โหลดไฟล์ TypeScript ของแต่ละเซ็ต (bt01.ts … bt11.ts, sd01.ts … ฯลฯ) จาก GitHub
- parse ด้วย regex เพื่อดึง `name`, `print` (=code), `type`, `rare`, `cost`, `gem`, `power`, `symbol`, `color`, `mainEffect` เป็นต้น
- แปลงเป็น `IncomingCard[]` แล้วรวมเข้าแคตตาล็อกเดิม (เพิ่มใหม่ + อัปเดต metadata)
- **ไม่ลบการ์ดเดิม** และ **ไม่เขียนทับ** จำนวนที่มี / โน้ต / ราคา / รูปที่แนบเอง
- การ์ดที่เปลี่ยนข้อมูลใน repo จะถูกอัปเดต metadata โดยคง internal ID เดิม (collection data ยังเชื่อมได้)
- บันทึก SyncStats ใน Settings และสร้าง ImportLogEntry ทุกครั้ง

### การซิงก์เป็นอัตโนมัติหรือต้องทำเอง?

**ต้องทำเองทุกครั้ง** — แอปนี้เป็น local-first ไม่มี background sync ไม่มี cron job ไม่มี push notification
ข้อมูลจะอัปเดตเมื่อคุณกดปุ่มเองเท่านั้น

### ข้อจำกัดของแหล่งข้อมูลชุมชน

> ⚠️ **ข้อสำคัญ**

- **ซอร์สโค้ด** ของโปรเจกต์ `kerlos/battle-of-talinchan-cards` อยู่ภายใต้ **MIT License**
- แต่ **ข้อมูลการ์ด** (ชื่อการ์ด, effect text, stats) เป็น **ลิขสิทธิ์ของ บริษัท พสุโลล จำกัด / ไลอ้อน เฮ้าส์ จำกัด**
- MIT license ครอบคลุมเฉพาะซอร์สโค้ด ไม่ใช่เนื้อหาการ์ด
- โปรเจกต์ต้นทาง **ไม่ใช่ข้อมูลทางการ** และ **ไม่ได้รับอนุญาตอย่างเป็นทางการ** จากเจ้าของเกม
- ใช้สำหรับ **การสะสมส่วนตัวเท่านั้น** ห้ามแจกจ่ายหรือนำไปเผยแพร่
- ข้อมูลอาจไม่ครบหรือไม่ถูกต้อง 100% เนื่องจากเป็นผลงานชุมชน
- **ไม่มีรูปการ์ด** ในแหล่งนี้ — ต้องแนบรูปเองในหน้ารายละเอียดการ์ด
- ถ้าโปรเจกต์ต้นทางเปลี่ยนรูปแบบไฟล์ script อาจ parse ไม่ได้ชั่วคราว

### ข้อจำกัดของ bottcg.com และ tamacard.com

ทั้งสองเว็บเป็น JavaScript SPA ที่โหลด render ผ่าน browser เท่านั้น:
- ไม่มี documented public API
- ไม่มีไฟล์ข้อมูลที่ดาวน์โหลดได้
- ไม่มีวิธีนำเข้าอัตโนมัติที่ถูกกฎหมายและไม่ต้องพึ่งบริการ scraping ที่มีค่าใช้จ่าย
- แอปนี้ไม่ scrape เว็บใดทั้งสิ้น

ถ้าต้องการใช้ข้อมูลจากเว็บเหล่านี้ ให้กรอกเองผ่านหน้า **"จัดการการ์ด"**
